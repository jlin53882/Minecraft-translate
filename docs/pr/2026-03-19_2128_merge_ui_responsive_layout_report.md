# Merge UI Responsive / Layout 修改清單｜工程師交付版

> 日期：2026-03-19 21:28
> 對象：負責調整 `app/views/merge_view.py` 的工程師
> 目標：改善 Merge UI 的可讀性、縮放表現與整體設定頁體驗

---

## 一、問題背景

目前 Merge UI 已具備功能，但畫面存在以下問題：

1. **閱讀壓力大**：資訊擠在一起，層級不清楚
2. **排版混亂**：設定項目之間缺乏明確區塊與間距
3. **縮小視窗時容易卡版**：外層縮小，但內層 UI 不會自然重排
4. **過度依賴橫向 Row 排版**：長 label + switch + input 會在窄寬度下撐開
5. **看起來像 debug 表單，不像正式設定頁**

---

## 二、設計原則

本次 UI 修改不是追求「像瀏覽器一樣自動縮放」，而是要達成：

### 核心目標
- **Responsive 重排**，不是單純縮小
- 外層變窄時，內層設定仍然可讀
- 每個設定項目是清楚獨立的 block
- 頁面可上下捲動，不會因內容過長被截斷

### 原則
1. **少用固定寬度**
2. **少用長 Row 橫向排版**
3. **每個設定項目改為垂直結構**：標題 → 控件 → 說明
4. **長說明文字一律下一行**
5. **以 Column 為主，不要把設定頁寫成表單列對齊**

---

## 三、必做修改清單

# A. 結構重整

## A1. 把「輸出與選項」區塊拆成 3 個清楚區段
目前設定內容全部擠在同一張卡片內，請改成以下結構：

```text
輸出與選項
├─ 輸出資料夾
├─ 一般選項
├─ 簡體中文（zh_cn）處理
└─ Patchouli 進階設定
```

### 具體要求
- `一般選項`：放 `只處理 lang 檔案`
- `簡體中文（zh_cn）處理`：放主開關 `啟用 zh_cn 檔案處理`
- `Patchouli 進階設定`：放其餘 3 個進階控制

---

## A2. 移除重複語意命名
目前有類似：
- `zh_cn 處理`
- `處理 zh_cn 檔案`

請收斂成：
- 區塊標題：`簡體中文（zh_cn）處理`
- 開關 label：`啟用 zh_cn 檔案處理`

避免同一區塊內兩個幾乎同義的標題。

---

# B. 設定項版型重做

## B1. 每個設定項改成「一卡一設定」
不要再用：
- 左邊 label
- 右邊 switch
- 下方再塞說明

請改成統一模板：

```text
設定標題
控件（Switch / TextField）
灰色說明文字
若 disabled，再顯示紅色原因文字
```

---

## B2. 具體套用項目
以下 4 個設定都要改成垂直 block：

1. `只處理 lang 檔案`
2. `啟用 zh_cn 檔案處理`
3. `只處理 lang 時跳過 zh_cn`
4. `允許 zh_cn 觸發跳過 en_us`
5. `Patchouli 有效翻譯比例門檻`

---

# C. `Row` 使用限制

## C1. 保留 Row 的地方
以下地方可保留 `Row`：
- 輸出資料夾欄位 + 開啟資料夾按鈕
- `新增 ZIP` 按鈕 + 簡短提示

## C2. 不應再使用 Row 的地方
以下地方請改為垂直排列：
- `Patchouli` 各設定項
- 長說明文字
- threshold label + input 的水平排列

### 特別禁止
不要再保留這類形式：

```python
ft.Row([ft.Text("翻譯有效性門檻："), self.patchouli_threshold_field])
```

---

# D. Threshold 欄位重整

## D1. 命名收斂
不要同時出現：
- `Patchouli 有效翻譯比例門檻`
- `翻譯有效性門檻`

請只保留一個正式名稱：

`Patchouli 有效翻譯比例門檻`

## D2. 版型要求
改為：

```text
Patchouli 有效翻譯比例門檻
[ 0.5 ]
預設 0.5，代表至少一半的文字檔被判定為有效 CJK 翻譯。範圍 0.0 ~ 1.0。
```

### 補充
若保留 `width`，欄位必須獨立一行，不能再與長 label 並排。

---

# E. Disabled / 互鎖呈現

## E1. 必須保留的 disabled 視覺規則
當 `process_zh_cn_files = false` 時：
- `skip_zh_cn_when_only_process_lang` 要灰化
- `patchouli_skip_en_us_when_zh_cn_exists` 要灰化

## E2. 每個 disabled 控件必須同時具備
1. 標題
2. 正常說明文字
3. disabled 原因文字
4. 灰化狀態

### 不能只灰掉不說原因
### 也不能只寫原因不灰掉

## E3. disabled 原因文字位置
必須放在該設定項 block 內、緊接控件或說明文字下方。

---

# F. Scroll（捲軸）策略

## F1. 外層必須支援垂直捲動
頁面內容較多，因此主內容區必須可上下 scroll。

## F2. 建議做法
- 外層主內容區：垂直 scroll
- ZIP 清單：固定高度 + scroll
- 日誌區：保留獨立 scroll

## F3. 不建議做法
不要讓每個小設定區塊都各自帶 scroll，避免互動體驗變差。

---

# G. 響應式（Responsive）要求

## G1. 本次最低要求
即使不做完整 breakpoints，也必須讓窄視窗下：
- 不出現明顯卡版
- 設定項可正常閱讀
- 不因某列過長而撐爆外層卡片

## G2. 建議方向
- 以 `Column` 為主
- 少用橫向對齊的 Row
- 長文字自然換行
- 避免固定寬度元件與長 label 同排

## G3. 若要進一步提升
可考慮後續再做：
- `page.on_resize`
- `ResponsiveRow`
- 寬版 / 窄版不同排列

但不是本輪必要條件。

---

## 四、建議的最終 UI 結構示意

```text
輸出與選項
├─ 輸出資料夾
│  └─ [TextField + folder button]
├─ 一般選項
│  └─ 只處理 lang 檔案
├─ 簡體中文（zh_cn）處理
│  └─ 啟用 zh_cn 檔案處理
└─ Patchouli 進階設定
   ├─ 只處理 lang 時跳過 zh_cn
   ├─ 允許 zh_cn 觸發跳過 en_us
   └─ Patchouli 有效翻譯比例門檻
```

---

## 五、驗收標準

### 必須達成
- [ ] 畫面不再像 debug 表單
- [ ] 設定項目之間有明確層級與間距
- [ ] 視窗縮小時不再出現明顯卡版
- [ ] 長說明文字不與 switch / input 擠在同一行
- [ ] threshold 欄位不再與長 label 水平硬排
- [ ] disabled 控件同時具備灰化 + 原因說明
- [ ] 外層頁面可上下捲動
- [ ] ZIP 清單 / 日誌區滾動行為正常

---

## 六、修改優先順序

1. **先拆區塊**：一般 / zh_cn / Patchouli
2. **再改設定項版型**：全部改成垂直 block
3. **拿掉容易卡版的 Row**
4. **整理 threshold 區塊**
5. **補外層 scroll**
6. **最後手動測試窄視窗 / 中視窗 / 寬視窗**

---

## 七、最終要求（給工程師）

這次修改的重點不是「讓 UI 自動縮小」，而是：

> **讓 Merge 設定頁在不同寬度下能自然重排、可讀、可操作。**

也就是：
- 用直式 block 取代擁擠的橫排表單
- 用 scroll 保底，而不是拿 scroll 掩蓋壞排版
- 把設定頁做成像正式產品，而不是臨時 debug 面板
