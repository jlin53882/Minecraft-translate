# Merge UI 新文案與排版定稿版｜工程師交付稿

> 日期：2026-03-19 21:40
> 目的：把目前「比較整齊的雜亂」收斂成真正可讀、可操作、像正式產品設定頁的 UI
> 適用檔案：`app/views/merge_view.py`

---

## 一、這次要解的不是功能，是 UI 體驗

目前 Merge UI 的問題不是功能缺失，而是：

1. **文字太多**
2. **同一件事講太多次**
3. **Patchouli 區塊太重，像說明文件**
4. **控件不是視覺主體，文字反而壓過操作本身**
5. **整體不像設定頁，比較像工程 debug 表單**

本版目標是：

> **每個設定只保留一個標題、一個控件、一句短說明。**

---

## 二、最終版面結構

```text
輸出與選項
├─ 輸出資料夾
├─ 一般選項
│  └─ 只處理 lang 檔案
├─ zh_cn 處理
│  └─ 處理 zh_cn 檔案
└─ Patchouli 進階設定
   ├─ 只處理 lang 時跳過 zh_cn
   ├─ 允許 zh_cn 觸發跳過 en_us
   └─ 有效翻譯比例門檻
```

---

## 三、文案定稿（直接照這版用）

# 1. 一般選項

## 設定標題
`只處理 lang 檔案`

## 說明文字
`開啟後，只處理語言檔；其他內容檔案會略過。`

---

# 2. zh_cn 處理

## 區塊標題
`zh_cn 處理`

## 設定標題
`處理 zh_cn 檔案`

## 說明文字
`關閉後，所有 zh_cn 檔案都會略過。`

> 注意：不要再另外出現「簡體中文（zh_cn）處理」+「啟用 zh_cn 檔案處理」兩層近義說法。
> 這裡只保留一個區塊標題 + 一個設定標題即可。

---

# 3. Patchouli 進階設定

## 區塊標題
`Patchouli 進階設定`

這一區塊請拆成 3 張獨立的小設定卡，不要再做成一整段大表單。

---

## 3-1. 只處理 lang 時跳過 zh_cn

### 設定標題
`只處理 lang 時跳過 zh_cn`

### 說明文字
`僅在「只處理 lang」模式生效。開啟後，zh_cn 的 lang 檔會直接跳過。`

---

## 3-2. 允許 zh_cn 觸發跳過 en_us

### 設定標題
`允許 zh_cn 觸發跳過 en_us`

### 說明文字
`開啟後，若 zh_cn 的有效翻譯比例達門檻，會跳過對應的 en_us。`

### Disabled 原因文字
`需先開啟「處理 zh_cn 檔案」後才能使用。`

> 這裡不要再保留過長版本：
> `目前已關閉「處理 zh_cn 檔案」，因此 zh_cn 無法參與 Patchouli 跳過判斷。`
> UI 上保留短版即可，閱讀壓力較低。

---

## 3-3. 有效翻譯比例門檻

### 設定標題
`有效翻譯比例門檻`

### 說明文字
`預設 0.5，代表至少一半的文字檔需被判定為有效翻譯。`

### 補充提示（可用 suffix / hint）
`範圍 0.0 ~ 1.0`

> 注意：不要同時出現：
> - `Patchouli 有效翻譯比例門檻`
> - `翻譯有效性門檻`
> - `Patchouli en_us 跳過決策的 CJK 有效比例（0.0~1.0）`
>
> 以上重複敘述都應收斂成：
> **標題 + 一句短說明 + 範圍提示**

---

## 四、排版規則定稿

# 1. 每個設定項都採同一模板

```text
設定標題
[控件]
說明文字
(若 disabled，再顯示原因文字)
```

---

# 2. 不再使用的版型

## 禁止這種寫法
```python
ft.Row([ft.Text("跳過條件："), self.skip_zh_cn_switch])
ft.Row([ft.Text("允許 zh_cn 觸發："), self.patchouli_skip_zh_cn_switch])
ft.Row([ft.Text("翻譯有效性門檻："), self.patchouli_threshold_field])
```

### 原因
- 太像 debug 表單
- 視窗縮小時容易卡版
- 文字與控件搶空間
- 讀起來像規格書，不像設定頁

---

# 3. 正確寫法方向

## 使用垂直 block
- 標題在上
- switch / input 在中
- 說明在下

## Patchouli 區塊
- 三個設定拆成三張白底小卡
- 每張卡只處理一件事
- 卡與卡之間保留明確間距

## 區塊外層
- 外層仍可使用淺灰底 Container
- 內層小卡用白底 / 圓角 / 輕 padding

---

## 五、視覺層級要求

| 層級 | 用途 | 建議樣式 |
|---|---|---|
| 區塊標題 | 一般選項 / zh_cn 處理 / Patchouli 進階設定 | 15~16px / semibold |
| 設定標題 | 各開關與門檻名稱 | 13~14px / medium |
| 控件 | Switch / TextField | 視覺主體 |
| 說明文字 | 功能說明 | 11~12px / 灰色 |
| disabled note | 禁用原因 | 11~12px / 紅色 |

---

## 六、捲軸策略定稿

### 1. 外層主內容區
- 必須支援垂直 scroll

### 2. ZIP 清單
- 可保留固定高度 + scroll

### 3. 日誌區
- 保留獨立 scroll

### 4. 設定區
- 不要每個設定小卡都加 scroll
- 靠外層捲動即可

---

## 七、最終驗收標準

### 必須達成
- [ ] 畫面不再像 debug 表單
- [ ] 每個設定只保留一個標題、一個控件、一句說明
- [ ] 不再有重複語意命名
- [ ] Patchouli 區塊明確拆成 3 張設定卡
- [ ] 視窗縮小時不再因長 Row 卡版
- [ ] disabled 控件有灰化 + 短版原因文字
- [ ] threshold 區塊簡潔、可讀、不重複命名

---

## 八、給工程師的最後要求

本輪不是補功能，而是做 **UI 收斂**。

請以這句作為最終方向：

> **把 Merge 頁面的設定區做成正式產品設定頁，而不是比較整齊的工程表單。**

也就是：
- 減字
- 減重複
- 強化控件主體
- Patchouli 區塊拆小
- 讓使用者一眼看懂能改什麼、改了會發生什麼
