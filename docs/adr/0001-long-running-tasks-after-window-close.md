# ADR-0001：關閉視窗後的長任務（#127）

- 狀態：**已接受方案 C**（決策：2026-10-04）；**#151 已實作**（見 `docs/RESUME_CAPABILITY.md`，Windows 實機驗證待完成）
- 相關：#126（關閉確認，已於 PR #149 落地）、#137（發佈形式）、#129（落盤）

## 背景

長任務在 App 行程內的 daemon thread 執行，關閉視窗等於行程結束、任務中斷。
PR #149 加入「關閉前確認、取消、drain、flush」作為短期緩解，但任務仍會停止。

## 事實盤點

**發佈形式**：打包 exe，資料放 exe 旁邊（見 `docs/DISTRIBUTION_AND_DATA_DIR.md`）。
打包後關閉視窗是否立即終止、不保證 flush，需 Windows 實機確認。

**續跑能力**（靜態盤點，皆未端到端驗證）：

| 流程 | 續跑機制 | 備註 |
|---|---|---|
| 機器翻譯（`core/lm_translator.py`） | 有 checkpoint：`compute_checkpoint_fingerprint`、`save_checkpoint`、`load_checkpoint`、`clear_checkpoint` | 每批後寫入；指紋比對防止套用到不同資料；路徑已改為走資料根目錄（`get_data_root()`），不再依賴工作目錄 |
| 翻譯快取 | 已寫入的快取不重翻 | 以 shard 與寫入間隔落盤，尚未落盤的部分關閉時可能遺失 |
| FTB / KubeJS / MD translator | 依快取分流，未發現獨立 checkpoint | 重開後靠快取跳過已翻項目 |
| 合併 / 提取 | 未發現續跑機制 | 重開需重跑 |

## 方案

| 方案 | 內容 | 主要取捨 |
|---|---|---|
| A 系統匣 | 關閉視窗只隱藏，行程與任務繼續 | Flet 1.0.1 無 tray API；需第三方函式庫與平台程式碼；使用者可能不知道仍在執行 |
| B 獨立背景行程 | 引擎移到 worker 行程，UI 重開可接回 | 最完整，但進度、取消、設定與金鑰共用、打包升級都要重做；需 pickle 友善的純資料介面 |
| C 只做重開後續跑 | 任務關閉後停止，重開後能從中斷處接續並提示 | 成本最低，與現有 checkpoint 對齊；前提是每批確實落盤 |

## 決策

採用 **C：只做重開後續跑**，不做 A（系統匣）與 B（獨立背景行程）。

**使用者要求（決策的一部分）**：重開後**不得自動繼續**。偵測到上次被中斷的任務時，
必須顯示提示，由使用者按下確認才續跑；使用者也可以選擇放棄（並清除 checkpoint）。

實作範圍：
1. （已完成）checkpoint 與錯誤記錄路徑改為走資料根目錄（`get_data_root()`）。
2. 驗證機器翻譯「中斷 → 重開 → 續跑」端到端，補測試（中斷點在切批中、寫快取中、剛開始；
   不漏翻、不重翻、不錯位）。
3. 啟動時偵測未完成的 checkpoint，顯示「上次被中斷的任務」確認對話框：
   - 確認 → 以同一批輸入續跑（沿用 `compute_checkpoint_fingerprint` 比對；指紋不符則不得續跑）。
   - 放棄 → `clear_checkpoint()`，不續跑。
   - 未做選擇前不得啟動任何翻譯、不得消耗 API 額度。
4. 確保 checkpoint 與快取在**每批完成後**確實落盤（flush/fsync），不依賴關閉時的清理。
5. 其他流程（FTB / KubeJS / MD / 合併 / 提取）本次只盤點續跑能力，不一定實作。

## 暫不處理

- A：Flet 1.0.1 無 tray API，且需在 Windows 打包環境實測第三方函式庫。
- B：工程量大，待 C 完成並確認不足時再評估。

## 風險與限制

- 關閉視窗後任務確實會停止（PR #149 的關閉確認與 flush 為緩解措施）。
- 續跑的前提是每批落盤；打包成 exe 後關閉時清理不一定會執行，需 Windows 實機驗證。
- checkpoint 指紋不符（輸入檔案已變動）時，應提示無法續跑，而不是靜默忽略。

## 實作紀錄（#151）

- 實作時發現：續跑的真正依據是**翻譯快取**（每批 fsync），checkpoint 只能當「沒做完」的標記與選項。
  舊實作依 checkpoint 位置跳過項目，快取沒有同步時會漏翻，已移除；改成每次都做快取分流，
  只翻譯未完成的項目。指紋改為涵蓋全部抽取項目，才不受快取進度影響。
- 啟動時偵測與對話框：`lm_resume`（引擎，唯讀）→ `resume_service`（service）→ `ResumePrompt`（外殼）。
- 關閉快取儲存時不寫 checkpoint（沒有可還原來源）。
- 其他流程的盤點見 `docs/RESUME_CAPABILITY.md`。
- **#164**：FTB／KubeJS／MD 也支援重開後續跑（整個任務一個標記、整條流程以同一組選項重新執行、來源檔案內容指紋、多任務共用一個對話框）；設計決定與限制見 `docs/RESUME_CAPABILITY.md`。
