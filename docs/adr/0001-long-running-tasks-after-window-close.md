# ADR-0001：關閉視窗後的長任務（#127）

- 狀態：**草案**（待決策；本文件不含實作）
- 相關：#126（關閉確認，已於 PR #149 落地）、#137（發佈形式）、#129（落盤）

## 背景

長任務在 App 行程內的 daemon thread 執行，關閉視窗等於行程結束、任務中斷。
PR #149 加入「關閉前確認、取消、drain、flush」作為短期緩解，但任務仍會停止。

## 事實盤點

**發佈形式**：打包 exe，資料放 exe 旁邊（見 `docs/DISTRIBUTION_AND_DATA_DIR.md`）。
打包後關閉視窗是否立即終止、不保證 flush，需 Windows 實機確認。

**續跑能力**（靜態盤點，皆未端到端驗證）：

| 流程 | 續跑機制 | 備註 |
|---|---|---|
| 機器翻譯（`core/lm_translator.py`） | 有 checkpoint：`compute_checkpoint_fingerprint`、`save_checkpoint`、`load_checkpoint`、`clear_checkpoint` | 每批後寫入；指紋比對防止套用到不同資料；路徑已改為走資料根目錄（`get_data_root()`），不再依賴工作目錄 |
| 翻譯快取 | 已寫入的快取不重翻 | 以 shard 與寫入間隔落盤，尚未落盤的部分關閉時可能遺失 |
| FTB / KubeJS / MD translator | 依快取分流，未發現獨立 checkpoint | 重開後靠快取跳過已翻項目 |
| 合併 / 提取 | 未發現續跑機制 | 重開需重跑 |

## 方案

| 方案 | 內容 | 主要取捨 |
|---|---|---|
| A 系統匣 | 關閉視窗只隱藏，行程與任務繼續 | Flet 1.0.1 無 tray API；需第三方函式庫與平台程式碼；使用者可能不知道仍在執行 |
| B 獨立背景行程 | 引擎移到 worker 行程，UI 重開可接回 | 最完整，但進度、取消、設定與金鑰共用、打包升級都要重做；需 pickle 友善的純資料介面 |
| C 只做重開後續跑 | 任務關閉後停止，重開後能從中斷處接續並提示 | 成本最低，與現有 checkpoint 對齊；前提是每批確實落盤 |

## 建議（待你確認）

先做 **C**：
1. （已完成）checkpoint 與錯誤記錄路徑改為走資料根目錄。
2. 驗證機器翻譯「中斷 → 重開 → 續跑」端到端，補測試（中斷點在切批中、寫快取中、剛開始）。
3. 在 App 啟動時顯示「上次被中斷的任務」。
4. 其他流程的續跑能力列為後續。

A、B 暫不做；若使用者仍需要「關掉也繼續」，再依 C 的結果評估。
