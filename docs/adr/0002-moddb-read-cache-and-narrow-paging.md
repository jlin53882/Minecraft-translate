# ADR-0002：資料庫唯讀快取與窄分頁

- 日期：2026-10-15
- 狀態：實作；效能驗收仍須區分暖快取、首次查詢與整體 UI
- 基準：PR #201，`f36b6ddc44812d2bdc71a5e52e18677c995fc8db`

## 決策

背景唯讀連線共用有界的序列化結果快取（128 筆、JSON 值合計最多 16 MB）。鍵包含
資料庫路徑、檔案身分、檔案／WAL 狀態及資料世代；回傳時解碼成個別物件，避免呼叫端
改動共用資料。寫入交易不讀取或發布這個快取。大量候選清單只使用程序內快取，不寫進
持久統計快取。所有產品寫入仍須透過交易遞增資料世代。

一般分頁先取得當頁 ID，再讀完整譯文、人工來源與歷史欄位。兩段查詢使用同一讀取
交易；已有外部交易連線的呼叫維持單一 SQL。預設 ID 查詢使用版本排序 covering index，
深分頁不先載入被 offset 略過的完整列。品質篩選可精確使用 SQL 的狀態直接分頁，
其他狀態保留 Python 判斷並重用當頁 ID／總數。

資料庫初始化只在審核觸發器的定義不同時重建它，避免正常重新開啟時改動 schema。

## 實測條件

Windows 11、Python 3.12.10、SQLite 3.47.1；備份資料有 710,437 個條目。
基準與候選程式在不同 process 執行，使用相同內容、相同來源優先序的隔離副本。
每個暖快取操作先執行一次未計時 warmup，再計時五次；p95 為這五次的 nearest-rank
統計，不代表長期 SLA。OS 檔案快取未控制。fresh-connection pass 每項只有一次樣本，
不將它描述為冷磁碟測試或有效的 p95。

供應的備份帶有 canonical-content 實驗版 schema-v6 標記，與上游的獨立審核 v6 不同。
隔離副本明確套用上游獨立審核轉換後才進行 A/B；未更改供應的原始檔案。上游不使用或
維護實驗版的兩張 canonical mapping 表，這份驗證不構成實驗版 mapping 完整性驗收。

## 驗收限制

暖快取改善不等於所有資料庫操作都能在 90–100 ms 完成。資料世代改變後需重算，
首次全庫總覽仍約 1.59 s、跨版本差異約 1.03 s；品質掃描、歷史排序與來源統計也有
超過 100 ms 的首次樣本。全庫聚合、correlated history lookup、temporary sort/group
與 Python 精確品質判斷仍是可定位的成本。

資料庫方法時間、UI 首次畫面變化、語意就緒、測試工具固定等待與整包掃描／遷移時間
必須分開回報。SQL 測試通過或暖快取 p95 達標，不作為完整 UI 或整批工作的達標證明。

## 正確性保護

- 快取跨連線重用、結果物件隔離、寫入失效、未提交交易不發布。
- UTF-8 值容量與 LRU 筆數上限、同世代檔案替換不重用舊結果。
- 所有排序／狀態分頁與完整查詢的結果比對，串流品質頁重用與寫入失效。
- 保留預設排序索引測試、revision/CAS、來源保留、審核與批次還原契約。
- 不用一般開啟資料庫的路徑自動重建全庫衍生資料，也不以過期結果換取延遲達標。
