## 評估後不建議做的優化

### 1. Views 都預先建立（真正的 Lazy Load）

**結論：不建議做**

理由：
- 實質提升不明顯（啟動減少 200-500ms，但需要大規模重構）
- 程式碼複雜度增加，維護成本提高
- 當前架構已經有 lazy import map，已有基本優化

### 2. ConfigView 啟動載入延後

**結論：不建議做**

理由：
- 實質提升不明顯（啟動減少 50-150ms）
- 風險較高（可能導致 UI 閃爍或狀態不一致）
- 可能影響使用者體驗（進入 ConfigView 時需要等待載入）

---

## 未來可以考慮的優化方向

1. **服務層非同步化** - 將檔案讀寫、API 呼叫等移到背景執行緒
2. **CacheView 資料載入優化** - 已經做了一部分（髒標記機制）
3. **UI 組件虛擬化** - 大量資料時使用虛擬列表減少記憶體使用

---

## 決策原則

每次 UI 優化前，必須回答：
1. 這個優化能帶來多少實質提升？
2. 程式碼複雜度增加多少？
3. 維護成本增加多少？
4. 風險是否可控？

如果答案不明顯或不值得，就不建議做。
