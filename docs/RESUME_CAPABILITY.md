# 重開後續跑：行為與各流程的續跑能力盤點（#151）

> 決策：`docs/adr/0001-long-running-tasks-after-window-close.md`（方案 C：只做重開後續跑，**不得自動繼續**）。
> 驗證清單：`docs/WINDOWS_VERIFICATION.md` 第 3 節。

## 核心觀念：快取是續跑的依據，checkpoint 是「沒做完」的標記

1. 每批翻譯完成後的順序是：**快取存檔（fsync）→ 輸出檔寫入 → checkpoint 寫入（原子寫入＋fsync）**。
   checkpoint 永遠最後寫，所以它不會領先已落盤的譯文。**只有快取 durable 之後才算完成的批次**：
   快取存檔失敗或該批項目被快取拒絕時，輸出檔仍會寫出，但**不寫 checkpoint**，任務以 FAILED 結束；
   checkpoint 維持上一個 durable 批次的狀態，重開後只會重翻沒有 durable 的那一批。
2. 重開後，翻譯照常抽取輸入並做**快取分流**：已完成批次的譯文是快取命中，直接寫回輸出；
   只有未完成的項目才送 API。**續跑不依 checkpoint 的位置跳過任何項目**——
   舊實作會用 `items[completed:]` 跳過前面的項目，當快取沒有同步（例如關閉快取儲存）時，
   已翻譯的內容會變回原文（漏翻）。這個路徑已移除，並有端到端測試鎖住。
3. checkpoint（`data/logs/translation_checkpoint.json`，版本 2）記錄：輸入／輸出資料夾、`export_lang`、
   `write_new_cache`、已處理／總數（僅供顯示）、**涵蓋全部抽取項目的指紋**、更新時間。
   指紋不受快取進度影響，所以重開後仍能比對；輸入內容或來源不同、舊格式都會被判為無法續跑。
4. `translator.enable_cache_saving = false` 時不寫 checkpoint（沒有可還原的來源）；殘留的舊標記會在下次翻譯時
   明確警告並捨棄。

## 啟動流程

| 步驟 | 行為 | 是否呼叫 API |
|---|---|---|
| 啟動偵測 | `lm_resume.peek_interrupted_task()` 讀 checkpoint（唯讀） | 否 |
| 對話框 | 顯示輸入／輸出資料夾與進度；背景執行緒比對輸入指紋（`check_resume_feasibility`，會讀輸入資料夾） | 否 |
| 續跑 | 僅在檢查通過後可按；切到機器翻譯頁，帶入上次的輸入與選項（dry-run 一律關閉）並開始，與按下「開始翻譯」相同 | 使用者按下後才會 |
| 放棄 | `clear_checkpoint()`；已翻譯內容仍保留在快取 | 否 |
| 稍後再說 | 什麼都不做，下次啟動再詢問 | 否 |
| 指紋不符／輸入資料夾不存在／舊格式 | 顯示原因，「續跑」停用，只能放棄或稍後；**不會靜默忽略** | 否 |

使用者做出選擇之前，不會啟動任何翻譯。

標記在「取消、失敗、金鑰耗盡、被關閉或強制結束」時都會保留（只有完整完成才清除），所以使用者主動取消過的任務，下次啟動也會被詢問；選「放棄」即可清除。

## 各流程的續跑能力盤點

| 流程 | 續跑機制 | 本次是否提供「重開後詢問續跑」 | 備註 |
|---|---|---|---|
| 機器翻譯頁（`translate_directory_generator`） | 翻譯快取（每批 fsync）＋ checkpoint 標記 | **是** | 中斷點（剛開始／批次之間／快取落盤後 checkpoint 前）都有端到端測試 |
| 一鍵流水線的翻譯步驟 | 同上（逐來源呼叫同一個函式） | 否 | 全域只有一個 checkpoint：上一個來源完成就清除，下一個來源再建立。中斷後重跑流水線，已完成部分由快取命中，很快跑完 |
| FTB／KubeJS／MD 翻譯 | 翻譯快取（共用批次迴圈）；各自寫 `translator_<plugin>_checkpoint.json` | 否（只盤點） | **發現**：`JsonCheckpointAdapter` 預設寫在相對路徑 `logs/`（相依工作目錄，未對齊資料根目錄 `get_data_root()`），且**沒有任何程式讀取它**（寫入專用）；原子寫入但未 fsync。續跑實際靠快取。建議另開 issue：路徑改走資料根目錄，或移除這個無人讀取的檔案 |
| 語系合併 | 無 | 否 | 沒有續跑機制；重開需重跑（輸出可重新推導） |
| JAR 提取 | 無 | 否 | 同上 |
| 打包 | 無，但 staging 是增量更新（#158） | 否 | 重跑成本低 |

## 已知限制

- 「剛開始、第一批尚未完成」就中斷時沒有標記，也沒有已完成內容；直接重新開始即可。
- 被中斷批次內「已回傳但尚未寫入快取」的項目會重新翻譯（最多一批）。
- 以 `untranslated`（批次縮到極限而回填原文）收尾的項目不寫入快取，續跑時會再試一次。
- 關閉視窗時任務確實會停止（PR #149 的確認、取消、flush 為緩解）；打包 exe 後關閉不保證執行任何清理，
  所以落盤都在每批完成時完成，不依賴關閉流程。
